backshots

Kubernetes-native backups that land as plain files on your NAS. Browse them, copy them, restore them. No keys, no S3, no special tooling.

plain files, no keysapp-consistent databasesrestores that are tested
Install with HelmGitHubDocs

Install

# add the chart repository
helm repo add backshots https://willuhmjs.github.io/backshots
helm repo update

# install the operator and point it at your NFS export
helm install backshots backshots/backshots -n backshots-system --create-namespace \
  --set store.create=true \
  --set store.nfs.server=192.168.1.5 \
  --set store.nfs.path=/volume1/k8s-backup

Back up an app in one manifest

apiVersion: backshots.io/v1alpha1
kind: BackupPolicy
metadata: {name: gitea-db, namespace: gitea}
spec:
  storeRef: default
  schedule: "0 * * * *"            # hourly
  source:
    type: postgres
    postgres:
      image: postgres:16            # pg_dump always matches your server
      host: postgres.gitea.svc
      passwordSecretRef: {name: postgres, key: password}
  verify:                          # restore it somewhere safe, prove it works
    schedule: "0 4 * * 0"
    database: gitea
    sql: ["select count(*) > 100 from repository"]
$ kubectl get backuppolicies -A      # example output
NAMESPACE   NAME        TYPE       SCHEDULE    LAST   SNAPSHOTS   VERIFIED   HEALTHY
gitea       gitea-db    postgres   0 * * * *   4m     26          true       True
gitea       gitea-data  files      0 3 * * *   9h     14          true       True

What you get on the NAS

gitea/gitea-db/2026-11-22T10-00-00Z/postgres/gitea.sql.gz   # plain SQL: zcat | psql
gitea/gitea-db/2026-11-22T10-00-00Z/postgres/globals.sql.gz # roles
gitea/gitea-data/2026-11-22T03-00-00Z/data/...               # a normal directory tree

Every folder is a complete snapshot. Unchanged files are hardlinked, so history is cheap. If the operator vanished tomorrow you would still restore with cp and psql.

Why it is different

Plain files

No repository format, no encryption keys, no object store to run. The backup is the thing you can open in your file manager.

Consistent databases

pg_dump and SQLite's online backup, run in your own database image so versions always match. Not a hot copy of data files.

Proven restorable

Verify jobs restore the latest snapshot into a scratch database and run your SQL assertions. A backup you never restored is a guess.

Restores you can kubectl

Apply a Restore. It checks inputs first, stops your app, restores, starts it again, and undoes itself if you delete it halfway.

Built-in retention

Hourly, daily, weekly and monthly counts per policy, pruned atomically. A snapshot only appears once it is complete.

Small and honest

One small controller. Tenant isolation on the share, authenticated metrics, health you can alert on. Alpha software, tested end to end.
